## 리스트/문자열/딕셔너리와 관련된 기본 함수들

### 1. list 내부의 최소·최대값 찾기 — `min()`, `max()`

```python
min(list이름), max(list이름)
```

> ✅ **해결된 궁금증 — 왜 `list.min()`이 아니라 `min(list이름)`인가**
> `append()`, `sort()` 같은 건 "리스트만의 고유한 기능"이라 리스트 클래스 안에 메소드로 들어있음. 반면 `min()`, `max()`, `sum()`, `len()`은 리스트뿐 아니라 튜플, 세트 등 여러 자료형에 공통으로 적용 가능한 범용 기능이라서, 특정 자료형에 종속시키지 않고 파이썬의 **내장 함수**로 따로 빼둔 것.
> ```python
> min([1,2,3])   # 리스트도 되고
> min((1,2,3))    # 튜플도 되고
> min({1,2,3})     # 세트도 됨
> ```
> "여러 자료형이 공통으로 쓰는 기능은 함수로, 그 자료형만의 고유 기능은 메소드로" 만든다는 게 대략적인 구분 기준.

### 2. list 내부 값 모두 더하기 — `sum()`

```python
sum(list이름)
```
`sum`, `min`, `max`를 쓸 때는 list가 모두 숫자로만 이루어져 있어야 함.

### 3. list 요소 순서 뒤집기 — `reversed()`

```python
lst = reversed([1,2,3])
```
이 함수는 무조건 어떤 변수에 담아줘야 사용 가능함.

> ✅ **해결된 궁금증 — `reversed()`가 여러 번 사용 안 되는 이유**
> `reversed()`는 리스트를 새로 만드는 게 아니라 **이터레이터**를 만듦. 이터레이터는 "한 번 다 꺼내면 그걸로 끝"임.
> ```python
> lst = reversed([1,2,3])
> for i in lst:
>     print(i)   # 3, 2, 1
> for i in lst:
>     print(i)   # 아무것도 안 나옴! 이미 다 꺼내져서 "빈 상태"가 됨
> ```
> 한 번 더 쓰고 싶으면 `reversed()`를 다시 호출해야 함.

### 4. list 요소를 반복할 때 현재 인덱스가 몇 번째인지 확인하기 — `enumerate()`

```python
list(enumerate(list이름))
# [(인덱스번호, '요소'), ...] 형태로, 리스트 안에 튜플 형식으로 뽑힘
```
`enumerate()` 결과를 `list()` 안에 안 넣으면 `<enumerate object at 0x02A43CB0>`처럼 뽑힘.

> ✅ **해결된 궁금증 — 왜 이상하게 뽑히는가**
> `enumerate()`도 `reversed()`처럼 **이터레이터를 만드는 함수**라서, 그냥 출력하면 "나는 이터레이터 객체다"라는 표시만 보여줌. `list()`로 감싸거나 `for`문에 넣어야 실제 값을 하나씩 꺼내볼 수 있음.

for문 돌릴 때 `enumerate()`를 쓰면 인덱스번호와 요소 두 개가 나오므로, `for a, b in enumerate(리스트):`처럼 인자를 두 개 둬야 함.

### 5. dict에서 요소를 반복할 때 enumerate처럼 쓸 수 있는 것 — `dict.items()`

```python
dic.items()
# dict_items([('a', 1), ('b', 2)])
```
이것도 키, 밸류값 두 개가 나오므로 인자 두 개(`for k, v in dic.items():`)를 둬야 함.

> ✅ **해결된 궁금증 — `dict.items()`는 왜 `list()`에 안 넣어도 결과가 보이는가, 왜 여러 번 써도 괜찮은가**
> `dict.items()`도 사실 이터레이터와 비슷한 **"뷰(view) 객체"**임. 그냥 출력해보면 `dict_items([('a', 1), ('b', 2)])`처럼 **내용을 미리보기 형태로 보여줘서** 이미 리스트가 된 것처럼 보인 것뿐이고, 진짜 리스트로 바꾸려면 여전히 `list(dic.items())`가 필요함.
> 다만 `dict_items`는 `reversed()`나 `enumerate()`처럼 "한 번 쓰면 소진되는" 진짜 이터레이터가 아니라 **뷰 객체**라서, **여러 번 반복해도 괜찮다는 차이**가 있음:
> ```python
> for k, v in dic.items():
>     print(k, v)
> for k, v in dic.items():   # 또 써도 정상 작동함! (reversed였다면 안 됐을 것)
>     print(k, v)
> ```
> 참고로 딕셔너리를 그냥 `for k in dic:`로 반복하면 key만 뽑히지만(4장 중단원 1에서 정리한 내용), `.items()`를 쓰면 key와 value가 튜플로 함께 나옴.

### 6. list comprehension

```python
리스트이름 = [표현식 for 반복자 in 반복할수있는것 if 조건문]
```
가독성이 떨어질 때는 이렇게 여러 줄로도 씀:
```python
리스트이름 = [
    표현식
    for 반복자 in 반복할수있는것
    if 조건문
]
```

> ✅ **해결된 궁금증 — if 조건문이 먼저 확인되는가, 실행 순서가 어떻게 되는가**
> 정확한 실행 순서:
> 1. `반복할수있는것`에서 하나씩 꺼내서 `반복자`에 담음
> 2. `if 조건문`을 확인 — **참이면 다음 단계로, 거짓이면 이번 값은 버리고 다음 값으로**
> 3. 조건을 통과한 값만 `표현식`에 넣어서 최종 리스트에 추가
> ```python
> [x for x in range(10) if x % 2 == 0]
> # 0,1,2...9 중에서 → 짝수만 걸러서(if) → 그대로(x) 리스트에 넣음
> # [0, 2, 4, 6, 8]
> ```
> 여러 줄로 나눠 쓴 방식이 실행 순서를 눈으로 보기엔 오히려 더 직관적임 (위에서부터 아래로 읽으면 실행 순서와 거의 일치).

### 7. 문자열 join

```python
"구분자".join(반복가능한것)
```

리스트의 요소를 문자열로 연결함. `join()`은 **문자열의 메소드**이고, 괄호 안에 넣는 대상(리스트, 튜플 등)은 **요소가 전부 문자열로만 이루어져 있어야** 함.

```python
",".join(["a", "b", "c"])    # 'a,b,c'   ✅ 리스트 안이 전부 문자열
"-".join("abc")                 # 'a-b-c'   ✅ 문자열 자체도 반복 가능한 대상이라 가능
",".join(["a", 1, "c"])         # ❌ TypeError! 숫자(1)가 섞여있으면 안 됨
```

> ✅ **해결된 궁금증 — split()이랑 뭐가 다른가**
> `split()`과 `join()`은 서로 **정반대 방향**으로 동작하는 짝꿍임.
> ```python
> "a,b,c".split(",")        # ['a', 'b', 'c']   ← 문자열을 "쪼개서" 리스트로 만듦
> ",".join(['a','b','c'])     # 'a,b,c'              ← 리스트를 "합쳐서" 문자열로 만듦
> ```
>
> | | 방향 | 시작 | 결과 |
> |---|---|---|---|
> | `split()` | 문자열 → 리스트 | 하나의 긴 문자열 | 쪼개진 여러 개의 문자열(리스트) |
> | `join()` | 리스트 → 문자열 | 여러 개의 문자열(리스트) | 하나로 합쳐진 문자열 |
>
> `split()`이 문자열에만 쓰이는 이유는, 애초에 "쪼갤 대상"이 문자열 하나뿐이기 때문. `join()`은 "합칠 재료(여러 개)"가 필요한데, 그 재료를 리스트·튜플 등 여러 형태로 받을 수 있어서 유연해 보이지만, `join()` 자체는 여전히 **문자열의 메소드**임(`"구분자".join(...)` 형태로만 쓰임). 결국 둘 다 "문자열"이 중심이 되는 메소드인데, `split()`은 "문자열을 쪼개서 밖으로 내보내는 것", `join()`은 "여러 개(문자열들)를 문자열 하나로 모으는 것"이라는 정반대 역할을 함.

## 이터레이터(Iterator)에 대해

```python
for 반복자 in 반복할수있는것:
```
여기서 "반복할 수 있는 것"을 프로그래밍 용어로 **이터러블(iterable)**이라고 함. 이터러블은 내부에 있는 요소들을 하나씩 꺼낼 수 있는 객체를 의미함 (리스트, 튜플, 문자열, 딕셔너리 등등).

그 이터러블 중에서 `next()` 함수를 이용해서 하나씩 꺼낼 수 있는 요소를 **이터레이터(iterator)**라고 함. 이터레이터는 반복문의 매개변수로 전달할 수 있고, `next(함수)`로 내부의 요소를 하나하나 꺼낼 수 있음.

> ✅ **해결된 궁금증 — `reversed()` 같은 함수는 왜 리스트를 안 내보내고 이터레이터를 내보내는가**
> **메모리 효율성 때문임.**
> ```python
> big_list = list(range(10000000))   # 천만 개 숫자, 메모리에 다 올라가 있음
>
> reversed(big_list)   # 이건 "천만 개를 거꾸로 뒤집은 새 리스트"를 미리 만드는 게 아니라,
>                         # "다음 걸 요청하면 그때 뒤에서부터 하나씩 꺼내줄게"라는 약속만 해둠
> ```
> 만약 `reversed()`가 진짜 새 리스트를 만들어 리턴했다면, 원본 리스트 크기만큼의 메모리를 한 번 더 써야 해서 두 배로 비효율적임. 이터레이터로 만들면 "필요한 순간에 하나씩만" 계산해서 주니까 메모리를 아낄 수 있음.

## 🔑 요약 — 왜 어떤 함수는 이상하게 출력되는가

| 함수 | 그냥 출력하면 | 이유 |
|---|---|---|
| `reversed(lst)` | `<list_reverseiterator object at ...>` | 진짜 이터레이터, 한 번 쓰면 소진됨 |
| `enumerate(lst)` | `<enumerate object at ...>` | 진짜 이터레이터, 한 번 쓰면 소진됨 |
| `dict.items()` | `dict_items([...])` | 뷰 객체, 미리보기로 보여줌, 여러 번 써도 됨 |

공통점: 셋 다 `list()`로 감싸거나 `for`문에 넣어야 실제 값을 하나씩 꺼내볼 수 있음. 다만 "여러 번 재사용 가능한가"는 서로 다름.
