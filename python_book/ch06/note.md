# 6장. 예외처리

## 오류의 종류

1. **구문 오류(syntax error)** — 실행 전 발생하는 오류
   괄호의 개수, 들여쓰기 문제 등으로 프로그램이 실행되기 전에 발생하는 오류
2. **예외 or 런타임오류(exception, runtime error)** — 프로그램 실행 중에 발생하는 오류

---

## 예외 처리

예외를 해결하는 모든 것을 이렇게 부름 (구문오류는 프로그램이 실행조차 안 되기 때문에 예외 처리 방법으로 해결할 수 없음. 코드를 수정해야 함.)

### 1. 조건문을 사용하는 방법

예를 들어 정수를 입력받아서 int로 바꾼 다음 어떤 걸 하는 프로그램에서 문자를 입력한다면 예외가 발생함. 이걸 처리하려면, 정수를 입력하지 않았을 때를 조건으로 구분해서 다른 처리를 하도록 해야 함.

```python
user_input_a = input("정수 입력 : ")

if user_input_a.isdigit():
    number_input_a = int(user_input_a)
    print("원의 반지름", number_input_a)
else:
    print("정수를 입력하지 않았습니다.")
```

### 2. try except 구문을 사용하는 방법

예외가 발생할 상황을 예측하고 모두 조건문으로 처리하는 것은 힘듦. 그래서 이 구문이 나옴.

```python
try:
    # 예외가 발생할 가능성이 있는 코드
except:
    # 예외가 발생했을 때 실행할 코드
```

```python
try:
    number_input_a = int(input("정수 입력 : "))
    print("원의 반지름", number_input_a)
except:
    print("무언가 잘못되었습니다.")
```

**try, except 구문과 pass 키워드 조합**
예외가 발생하면 일단 처리해야 하지만, 해당 코드가 딱히 중요하지 않다면 일단 프로그램이 강제종료되는 것을 막자는 목적으로 except 구문에 아무것도 안 넣고 pass만 씀.

```python
try:
    코드
except:
    pass
```

**try except else 구문**
예외가 발생하지 않았을 때 실행할 코드를 정할 수 있음.

```python
try:
    # 예외가 발생할 가능성이 있는 코드
except:
    # 예외가 발생했을 때 코드
else:
    # 예외가 발생하지 않았을 때 실행할 코드
```

```python
try:
    number_input_a = int(input("정수 입력 : "))
except:
    print("무언가 잘못되었습니다.")
else:
    print("원의 반지름", number_input_a)
```

**finally**
예외 처리 구문에서 가장 마지막에 쓰이는 구문. 예외가 발생하든 안 하든 무조건 실행할 때 쓰는 코드.

**예외처리 구문은 반드시 다음 규칙을 지켜야 함**
1) try 구문은 단독 사용 불가, 반드시 except 또는 finally와 함께 사용
2) else 구문은 반드시 except 구문 뒤에 사용

**따라서 가능한 조합**
1) try + except
2) try + except + else
3) try + except + finally
4) try + except + else + finally
5) try + finally

**finally의 진짜 위력**: 보통 반복문 또는 함수 내부에 있을 때 위력이 발생함. 만약 어떤 함수 안에서 try 구문 내부에 return 키워드가 있다면, return이 되더라도 finally는 무조건 실행됨. 그렇기 때문에 문서를 닫는 작업처럼 반드시 해야 하는 일을 finally 안에 넣어놓으면 try 안에 return이 있더라도 반드시 문서를 닫을 수 있음. 반복문에서 break로 빠져나갈 때도 마찬가지.

## 예외 객체

예외가 생기면 예외와 관련된 정보가 생김. 이런 예외 정보는 예외 객체에 저장됨.

### 1. 사용법
```python
try:
    # 예외가 발생할 가능성이 있는 구문
except 예외의 종류 as 예외 객체를 활용할 변수 이름:
    # 예외가 발생했을 때 실행할 구문
```

### 2. 처음 예외 객체를 사용할 때 예외 종류가 뭔지 모르겠으면, `Exception` 사용 (참고로 Exception은 클래스임)

### 3. 왜 쓰는가 — 실제 상황으로 예를 들면

챗봇 서비스를 운영한다고 해보자. 사용자 1000명이 매일 사용하는데, 가끔 GROQ API 호출이 실패하는 경우가 있음. 이때 예외 객체를 안 쓰면:

```python
try:
    response = client.chat.completions.create(...)
except:
    print("오류 발생")   # 그냥 이것뿐 — 뭐가 문제인지 전혀 모름
```

**문제**: 사용자한테 "오류 발생"만 뜨고, 개발자는 이 오류가 정확히 뭐 때문에 났는지 전혀 알 수가 없음. API 키가 잘못됐는지, 네트워크가 끊겼는지, 요청 형식이 틀렸는지, 서버가 다운됐는지 — 전혀 구분이 안 됨.

**예외 객체를 쓰면**:
```python
try:
    response = client.chat.completions.create(...)
except Exception as e:
    error_info = f"에러 종류: {type(e)}, 메시지: {e}, 발생 시각: {현재시각}"
    send_email_to_developer(error_info)   # 개발자에게 자동으로 메일 발송
    print("일시적인 오류가 발생했습니다.")   # 사용자에겐 친절한 메시지만
```

**이렇게 하면**: 사용자는 "오류가 발생했다"는 것만 보지만, 개발자는 이메일로 "정확히 몇 시에, 어떤 종류의 에러가, 어떤 메시지와 함께 발생했는지" 자동으로 받아볼 수 있음. 하루에 이런 에러가 5번 났다면, 5개의 이메일이 쌓이고, 그걸 보면서 "GROQ API가 자주 타임아웃 나는구나. 재시도 로직을 추가해야겠다"처럼 실제 서비스를 개선할 방향을 찾을 수 있음.

> 예외 객체 없이 그냥 `except:`만 쓰면 "뭔가 잘못됐다"는 것만 알고 끝이지만, 예외 객체(`as e`)를 쓰면 "정확히 무엇이, 왜 잘못됐는지"를 데이터로 남길 수 있어서, 나중에 그 데이터를 모아 서비스를 개선하는 데 쓸 수 있음. 소규모로 연습할 땐 체감이 잘 안 되지만, 실제 서비스가 커지고 사용자가 많아질수록 "왜 실패했는지 기록하는 것" 자체가 매우 중요해짐.

### 4. 예외 객체를 사용하면 except 구문을 if 조건문처럼 사용해서 예외를 구분할 수 있음

하나의 코드에서 두 가지 이상의 예외가 나올 수 있음. 그럴 때:

```python
try:
    # 예외가 발생할 가능성이 있는 구문
except 예외의 종류a:
    # 예외a가 발생했을 때 실행할 구문
except 예외의 종류b:
    # 예외b가 발생했을 때 실행할 구문
```

```python
lst = [256, 42, 35, 68, 3]

try:
    number_input = int(input("정수입력:"))
    print(f"{number_input}번째 요소 : {lst[number_input]}")
except ValueError:
    print("정수를 입력해주세요")
except IndexError:
    print("리스트 인덱스를 벗어났어요.")
```

### 5. 4번처럼 사용할 때도 예외 객체를 붙여서 활용 가능
```python
except ValueError as exception:
```

### 6. 예외 조건에 일치하는 게 없으면 프로그램이 강제종료됨

except 구문으로 예외를 구분해놨는데, 예외 조건에 일치하는 게 없으면 당연히 예외가 발생하며 프로그램이 강제종료됨. 그래서 꼭 마지막엔 모든 예외를 감당할 수 있는 Exception을 넣어주는 게 좋음.

```python
except Exception as exception:
    print("예상치 못한 예외가 발생했습니다.")
```

### 7. 강제로 예외를 발생시키는 경우 — raise

반대로 강제로 예외를 발생시키는 경우가 있음. 예를 들어 이 부분을 넘어가면 나중에 큰 문제가 발생하는 경우거나, 아직 구현하지 않은 부분인 경우. 그냥 넘어가지 못하고 그곳에서 강제 종료시켜야 할 때 쓰는 게 `raise 예외 객체` 구문임. (뒤에 class 배울 때 더 배울 예정, 지금은 알아만 둘 것)

## assert

조건이 false일 때 발생하는 에러. 디버깅 모드에서만 작동하지만, 파이썬은 기본적으로 디버깅 모드임.

```python
x = 3
assert x % 3 == 0, '3의 배수가 아닙니다.'
print('3의 배수입니다.')
```

> ✅ **해결된 궁금증 — assert 뒤 구문이 true/false일 때 각각 어떻게 동작하는가**
> - `x % 3 == 0`이 **참**이면 → assert는 아무 일도 안 하고 그냥 통과 → 다음 줄(`print`) 실행됨
> - `x % 3 == 0`이 **거짓**이면 → `AssertionError`라는 에러가 발생하면서 프로그램이 그 자리에서 멈춤. 이때 콤마 뒤에 적은 문자열(`'3의 배수가 아닙니다.'`)이 **그 에러 메시지로 사용**됨
>
> ```python
> x = 5
> assert x % 3 == 0, '3의 배수가 아닙니다.'
> ```
> ```
> AssertionError: 3의 배수가 아닙니다.
> ```
>
> "콤마 뒤 코드가 실행된다"기보다는, **"콤마 뒤 문자열이 에러가 발생했을 때 화면에 보여줄 설명문으로 쓰인다"**가 더 정확한 표현. 그래서 `print('3의 배수입니다.')`는 거짓일 때 실행되는 게 아니라, 애초에 에러가 나서 프로그램이 멈춰버리니까 아예 도달을 못 하는 것.

**assert 요약**

| 조건 | 결과 |
|---|---|
| 참(True) | 아무 일 없이 통과, 다음 코드 계속 실행 |
| 거짓(False) | `AssertionError` 발생, 프로그램 중단(이후 코드는 실행 안 됨), 콤마 뒤 문자열이 에러 메시지로 표시됨 |
