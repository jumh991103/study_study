## 재귀함수

### 문제
식탁에 나누어 앉으려고 하는데, 한 사람만 앉는 테이블이 없게 그룹지어야 하고, 인원수를 나누는 패턴만 구하면 되며, 누가 어디에 앉는지는 신경 쓰지 않는다. 한 개의 테이블에 앉을 수 있는 최대 사람 수는 10명이고, 100명의 사람이 하나 이상의 테이블에 나누어 앉는 패턴의 경우의 수를 구하는 문제.

```python
min = 2
max = 10
total = 100
memo = {}

def problem(left, min):
    key = str([left, min])

    if key in memo:
        return memo[key]

    if left < 0:
        return 0

    if left == 0:
        return 1

    count = 0
    for i in range(min, max + 1):
        count += problem(left - i, i)

    memo[key] = count

    return count

problem(100, 2)
```

### 애자일 방식으로 접근하기 — 처음엔 이해가 안 됐던 코드, 단계별로 쌓아가며 이해

**1단계 — 문제를 훨씬 작게 줄여서 손으로 풀어보기**

100명을 바로 생각하지 말고, 인원을 5명, 테이블 최대 3명으로 줄여서 손으로 직접 세어봄.
```
5명을, 한 테이블에 2~3명씩(1명 테이블 금지) 나누는 방법은?
- 2+3
- 3+2 → "2+3"과 "3+2"는 순서만 다르지 사실 같은 패턴 (문제에서 "누가 어디 앉는지 신경 안 씀" = 순서도 상관없다는 뜻)
```
결론: 5명을 나누는 패턴은 딱 1가지 (`2+3`).

이렇게 손으로 먼저 풀어보면서 "이 문제가 정확히 뭘 요구하는지" 감을 잡는 게 애자일의 첫 단계. 코드부터 짜지 않고 문제를 이해하는 데 먼저 시간을 씀.

**2단계 — "한 테이블만 채우고, 나머지는 나중에 생각한다"는 아이디어로 단순화**

핵심 아이디어: "100명 전체를 한 번에 나누는 방법"을 고민하지 말고, "첫 번째 테이블에 몇 명을 앉힐지"만 정하고 나머지는 똑같은 문제를 다시 푼다고 생각하면 훨씬 쉬워짐.
```
100명을 나누는 방법
= (첫 테이블에 2명 앉히고, 나머지 98명을 나누는 방법의 수)
+ (첫 테이블에 3명 앉히고, 나머지 97명을 나누는 방법의 수)
+ (첫 테이블에 4명 앉히고, 나머지 96명을 나누는 방법의 수)
+ ...
+ (첫 테이블에 10명 앉히고, 나머지 90명을 나누는 방법의 수)
```
이게 바로 재귀. "100명 문제"를 풀려고 "98명 문제", "97명 문제"...를 부르고 있음. 같은 종류의(더 작은) 문제를 반복해서 부르는 것이 재귀함수의 핵심.

**3단계 — 제일 작은 경우(종료 조건)부터 코드로 만들기**

"더 이상 나눌 사람이 없을 때"가 언제인지부터 정해야 무한 반복에 안 빠짐.
```python
def problem(left, min):
    if left < 0:      # 남은 인원이 음수 → 방금 앉힌 인원수가 너무 많았다 → "실패", 0가지
        return 0
    if left == 0:      # 남은 인원이 딱 0명 → 완벽하게 다 나눴다 → "성공", 1가지로 셈
        return 1
```
여기까지가 애자일에서 "제일 작은 동작하는 버전". 아직 진짜 로직(테이블 채우기)은 없지만, "언제 멈춰야 하는지"만 먼저 확정해두는 것.

**4단계 — 진짜 로직(테이블 채우기) 추가**
```python
count = 0
for i in range(min, max + 1):    # 이번 테이블에 min명부터 max명까지, 하나씩 시도
    count += problem(left - i, i)   # 이번 테이블에 i명 앉혔다 치고, 나머지(left-i)를 또 나눔
return count
```
`min`이 반복문 안에서 계속 바뀌는 이유: 두 번째 테이블부터는 항상 "이전 테이블 인원수 이상"만 시도하게 해서, `2+3`과 `3+2`를 서로 다른 걸로 중복 세지 않기 위한 장치. "테이블 인원수는 항상 커지거나 같게만 진행한다"는 규칙을 강제한 것.

**5단계 — 반복되는 계산을 캐싱(메모이제이션)으로 최적화**
```python
memo = {}
key = str([left, min])
if key in memo:
    return memo[key]
```
"같은 (left, min) 조합을 여러 번 계산할 수 있으니, 한 번 계산한 건 저장해뒀다가 재사용하자"는 최적화. 이건 로직이 다 완성된 다음, "느리다"는 문제가 생기면 그때 추가하는 개선 단계 (처음부터 이것까지 생각하면 너무 복잡해짐 — 애자일답게 "일단 되는 것부터, 그다음 개선").

**전체 흐름 요약**
```
1. 문제를 작은 숫자로 줄여서 손으로 풀어보기
2. "첫 부분만 정하고, 나머지는 같은 문제를 다시 푼다"는 재귀 아이디어 떠올리기
3. 종료 조건(더 안 나눠도 될 때)부터 코드로 만들기
4. 진짜 로직(테이블 채우기 시도) 추가하기
5. 느리면 그때 캐싱으로 최적화하기
```

## 튜플

1. 요소를 하나만 갖는 튜플의 경우엔 `(1,)`처럼 작성해줘야 함. 머신러닝에서 자주 나오니까 기억해둘 것.

2. 리스트와 거의 비슷한 튜플을 언제 사용하는가
   1) 괄호가 없어도 튜플로 인식될 수 있을 때 괄호를 생략해도 됨.
      예를 들어 가끔 `a,b,c = 10, 20, 30`처럼 써줄 때가 있는데, 사실 이건 `(a,b,c) = (10,20,30)`인 것.
      그래서 `a, b = 10,20`이라고 해놓고 둘을 바꾸고 싶을 때 `a,b = b,a`처럼 자주 씀.
      어디서 쓰였는지 예를 들면, enumerate 예시 중에 `for i,value in enumerate([1,2,3,4,5])`처럼 있었는데, `i,value`도 사실 `(i,value)`였던 것.

## 람다

1. 1회용 함수 만들 때 많이 사용
2. 아주 간단한 파라미터가 정의되거나 반환하는 함수일 경우 사용
3. 한 줄짜리 간단한 함수 만들 때 많이 사용

람다를 설명하기 전에 함수의 매개변수로 함수를 먼저 알아보자면, 이를 '콜백 함수'라고 함. 콜백함수 중에 대표적인 표준함수로 `filter()`, `map()`이 있음.

1. `map(함수, 리스트)` -> 리스트의 요소를 함수에 넣고 리턴된 값으로 새로운 리스트를 구성해주는 함수
2. `filter(함수, 리스트)` -> 리스트의 요소를 함수에 넣고 리턴된 값이 True인 것으로, 새로운 리스트를 구성해주는 함수

이 두 개는 제너레이터임. 그래서 결과를 눈으로 보고 싶으면 리스트로 감싸줘야 함: `list(map(함수, 리스트))`처럼.

이제 람다를 설명하자면, 간단하게 함수를 선언하는 방법인데, `함수명 = lambda 매개변수 : 리턴값`처럼 쓰면 됨. 굳이 이거 써야 하나 싶지만, `map`, `filter`처럼 콜백함수 쓸 때 매개변수로 받는 함수가 매우 짧은 함수라면, `map(lambda 매개변수 : 리턴값, 리스트)`처럼 코드를 확 줄일 수 있음.

## 파일 처리

파이썬 표준함수 중에 파일 관련 처리를 하는 함수가 있음.

1. 파일 열고 닫기
   1) `파일 객체 = open(문자열:파일경로, 문자열:읽기모드)` -> 모드에는 `w`, `a`, `r`이 있음 (새로쓰기, 이어쓰기, 읽기)
   2) `파일 객체.close()`

### with 키워드

```python
with open(문자열:파일경로, 문자열:모드) as 파일 객체:
    문장
```
형식으로 쓰이는데, 이는 `open`, `close` 함수를 쓰다 보면 프로그램이 길어지면서 두 함수 사이에 많은 코드가 들어가게 되고, 그러면 파일을 열고 닫지 않는 실수가 생길 수 있음. 그걸 방지하기 위해 쓰는 것. `with` 구문이 종료되면 자동으로 파일이 닫힘. 파이썬에선 다루지 않지만, 네트워크로 흐르는 길을 열고 닫을 때도 사용함 (Streamlit 사용할 때 많이 봤던 것 같음).

2. 파일에 텍스트 쓰기
   `파일 객체.write(문자열:쓰고싶은 문장)` -> 파일 오픈할 때 쓰기 모드여야 함.

3. 파일의 텍스트 읽기
   `파일객체.read()` -> 자동으로 내부의 데이터를 모두 읽어 출력함. 파일 오픈할 때 읽기 모드여야 함.

4. 파일의 텍스트 한 줄씩 읽기
```python
for 한 줄을 나타내는 문자열 in 파일 객체:
    처리
```
보통 csv 파일 같은 데서 한 줄씩 뭔가를 처리해야 할 때 자주 사용함.

> ✅ **해결된 궁금증 — "한 줄을 나타내는 문자열"이란 이름이 파이썬에 정해져 있나?**
> 아니, 정해진 이름이 아니라 그냥 관례적으로 많이 쓰는 변수명임 (보통 `line`). `i`, `x`, 아무 이름이나 써도 문법적으로는 똑같이 작동함. `line`을 관례로 쓰는 이유는 "이게 파일의 한 줄(line)을 나타낸다"는 걸 코드 읽는 사람이 바로 알 수 있게 하기 위해서.

### 예시 코드
```python
with open("info.txt", "r") as file:
    for line in file:   # 한 줄씩 실행
        (name, weight, height) = line.strip().split(", ")   # 한 줄을 본 걸 세 가지 변수에 나눠 담음

        if (not name) or (not weight) or (not height):
            continue   # name, weight, height 중 하나라도 없으면 이번 회차 반복은 그냥 지나감

        bmi = int(weight) / (int(height) / 100) ** 2   # bmi 구하는 공식, 문자열로 저장되어 있으니 int로 변환
        result = ""

        if 25 <= bmi:
            result = "과체중"
        elif 18.5 <= bmi:
            result = "정상 체중"
        else:
            result = "저체중"

        print('\n'.join([
            "이름: {}",
            "몸무게 : {}",
            "키 : {}",
            "BMI : {}",
            "결과 : {}"
        ]).format(name, weight, height, bmi, result))

        print()
```

> ✅ **해결된 궁금증 — `'\n'.join([...]).format(...)`이 하는 일**
> 두 개가 순서대로 실행되는 것.
> ```python
> '\n'.join([
>     "이름: {}",
>     "몸무게 : {}",
>     ...
> ])
> ```
> `join()`은 리스트 안의 문자열들을 지정한 구분자로 이어붙이는 함수. `'\n'.join([...])`은 "이 리스트 안의 문자열들을 줄바꿈으로 이어붙여라"는 뜻:
> ```
> "이름: {}\n몸무게 : {}\n키 : {}\n..."
> ```
> 5개의 짧은 문장을 한 줄에 하나씩 보여주고 싶어서 이렇게 미리 줄바꿈을 넣어서 하나의 긴 문자열로 합친 것.
>
> 그다음 `.format(name, weight, height, bmi, result)`로, 문자열 안에 있던 `{}` 자리(총 5개)에 순서대로 값을 채워 넣음.
>
> 정리하면: "여러 줄짜리 출력 틀을 리스트로 만들어두고 → 줄바꿈으로 하나로 합치고 → 값을 채워 넣는" 3단계 조합. `print(f"이름: {name}\n몸무게: {weight}\n...")`처럼 한 줄로 써도 똑같은 결과가 나오는데, 항목이 많아지면 이렇게 리스트+join 방식이 더 읽기 편해서 종종 쓰는 패턴.

## 제너레이터

파이썬의 특수한 문법 구조. 이터레이터를 직접 만들 때 사용하는 함수. 함수 내부에 `return` 대신 `yield` 키워드를 사용하면 그 함수는 제너레이터 함수가 되고, 함수를 호출해도 내부 코드가 바로 실행되지는 않음.

그래서 `next()` 함수를 사용해서 함수 내부 코드를 실행해주는데, `yield` 키워드를 만나면 거기까지만 실행하고 `yield` 키워드 뒤에 입력된 값을 출력함. 그리고 다시 실행하면 다음 `yield` 키워드까지 실행함. 그러다 `next()` 함수를 더 썼는데 `yield` 키워드가 없으면 `StopIteration`이라는 예외가 발생함.

### `reversed()` 함수를 제너레이터로 직접 구현해보기

`reversed()` 함수가 이터레이터라는 걸 배웠는데, 그럼 이걸 제너레이터로 직접 구현할 수도 있다는 걸 확인.

```python
def my_reversed(lst):
    idx = len(lst) - 1     # 마지막 인덱스부터 시작
    while idx >= 0:
        yield lst[idx]       # 이 자리까지만 실행하고 값 하나 내보냄
        idx -= 1               # 다음 next() 호출 때 여기부터 다시 실행

# 사용해보기
gen = my_reversed([10, 20, 30])
print(next(gen))   # 30
print(next(gen))   # 20
print(next(gen))   # 10
print(next(gen))   # StopIteration! 더 이상 줄 게 없음

# for문으로도 똑같이 쓸 수 있음
for x in my_reversed([10, 20, 30]):
    print(x)   # 30, 20, 10
```

**동작 원리**: `yield`를 만나면 딱 거기까지만 실행하고 함수 실행을 "일시정지"함. `next()`를 다시 부르면, 멈췄던 바로 그 지점(`idx -= 1` 줄)부터 이어서 실행됨. 리스트를 통째로 뒤집어서 새로 만드는 게 아니라, "다음 값이 뭔지 필요할 때마다 하나씩만" 계산하니까 진짜 `reversed()`처럼 메모리를 아끼는 방식이 되는 것.
